# Introduction

The Cisco Modeling Labs platform comes bundled with a set of node definitions. Each node definition already has a corresponding image definition, allowing you to immediately start modeling labs. To match the device version in your lab with the version that is used in a real network, it may sometimes be necessary to upload an additional VM image, create a new image definition, and link it to an existing node definition. This ensures that the device version in your lab aligns perfectly with what is used in the real network.

In more advanced scenarios, you may want to create entirely new nodes, such as third-party VM images—for example, a Windows VM—that are not bundled by default. For this purpose, you must create a new node definition and a corresponding image definition, which will then be linked to the newly created node definition.

## Note

For additional resources, such as the image and YAML files that are not included in the reference Cisco Modeling Labs platform, see [https://github.com/CiscoDevNet/cml-community](https://github.com/CiscoDevNet/cml-community)


you will learn how to import and manage image and node definitions, a skill that will enable you to simulate various Cisco and other network devices to use in your labs.

# Node Definitions

In Cisco Modeling Labs, a node definition represents a type of a virtual device. Each node in a Cisco Modeling Labs lab has an associated node definition that describes the node and the properties of the node, such as the number of available interfaces, their names, and other essential parameters required to start the VM. It is crucial to understand that a node definition represents a family or type of a virtual device, not a particular VM image.

## Note

When adding a new node to Cisco Modeling Labs, you must first create a node definition, followed by creating a corresponding image definition.

The node definition details all the properties that enable Cisco Modeling Labs to start a VM that is associated with the node definition. To create a new node definition, you can either upload a YAML file for that node or create it from scratch. If you choose to create a new node definition from scratch, you must be familiar with the virtualization details for that type of device.

## Note

When creating a new node definition, refer to the guide available at [https://developer.cisco.com/docs/modeling-labs/#!creating-a-new-node-definition](https://developer.cisco.com/docs/modeling-labs/#!creating-a-new-node-definition), which describes the node definition properties in Cisco Modeling Labs. Use this developer guide together with your virtual device installation and configuration documentation to choose the correct values for your custom node definition.

# Image Definitions


An image definition within Cisco Modeling Labs represents a link between a VM image and a node. For example, the image definition links the CAT 8000V node to a particular Cisco IOS XE Software image. Usually, one node definition corresponds to each device type, but multiple image definitions can be attached to a single node definition (such as different software versions, for example). In this way, you can choose from various image definitions when using this node in your Cisco Modeling Labs labs.


## Note

When you create a new image definition, you need to associate it with an existing node definition. You can add a new software version to an existing node without any problems, as the node definition already exists. However, if you want to add a completely new node, you must first create a node definition for that device.

## Import Node Definitions

Within Cisco Modeling Labs, you will find a library of reference platforms encompassing various Cisco network devices, Linux server images, traffic generators, unmanaged devices ready for you to use in your labs, and so on. However, sometimes you need a device that is not part of the reference platform at all, such as the Cisco Certified DevNet Expert Candidate Workstation (CWS), a Linux-based practice workstation published by Cisco in the Cisco Modeling Labs community node definitions repository. Unlike an older image of a device you already use in production, the CWS has no existing node definition inside Cisco Modeling Labs to build from, so you will import it as a completely new node definition. To start, review the steps on how to add a node definition.

## Task 1: Import Node Definitions


Sometimes, you may want to use devices in your Cisco Modeling Labs topologies that are not part of the reference platform. This could be because you need a different version of a certain device, or a completely different type of device altogether. The CWS is a good example of the latter: Cisco publishes its node definition on GitHub at [https://github.com/CiscoDevNet/cml-community/tree/master/node-definitions/cisco/cws](https://github.com/CiscoDevNet/cml-community/tree/master/node-definitions/cisco/cws), but it is not bundled with Cisco Modeling Labs by default. In this lab, you will import that node definition and add a brand-new device type to your Cisco Modeling Labs instance.

1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. From the Dashboard, navigate to **Tools > Node and Image Definitions**.

Notice that the **Node Definitions** tab is chosen by default.

3. Choose an existing **CAT 8000V** node definition to review, so you have something to compare against once you import a genuinely new device type.

Carefully observe the values. Focus on the **Available Image Definitions** field. If there are several image definitions linked with this node definition, you will see them here. Choosing any will lead you to the **Image Definition Editor**.


## Note

When deleting a node, make sure that there are no instances of this node being used in labs, preventing the node from being deleted.

4. On your Student PC, locate the **cws.yaml** node definition file, already saved in the **cml-images** folder which is located inside the **Downloads** folder, and open it in Notepad or any other plaintext editor.

This file is the CWS node definition published by Cisco. Unlike the CAT 8000V node definition you just reviewed, this device is not one of the reference platforms bundled with Cisco Modeling Labs, so there is no existing definition to download and modify. You are adding an entirely new device type instead.

```
id: cws
sim:
  linux_native:
    driver: server
    libvirt_domain_driver: kvm
    disk_driver: virtio
    nic_driver: virtio
    ram: 8192
    cpus: 4
    data_volume: 1
    cpu_limit: 100
    video:
      memory: 4
      model: cirrus
inherited:
  image:
    ram: true
    cpus: true
    cpu_limit: true
    data_volume: true
    boot_disk_size: true
  node:
    ram: true
    cpus: true
    cpu_limit: true
    data_volume: true
    boot_disk_size: true
general:
  nature: server
  description: Cisco Certified DevNet Expert Candidate Workstation
  read_only: false
schema_version: 0.0.1
configuration:
  generator:
    driver: ubuntu
device:
  interfaces:
    physical:
      - ens3
      - ens4
      - ens5
      - ens6
    has_loopback_zero: false
    default_count: 1
    serial_ports: 1
boot:
  timeout: 180
  completed:
    - Welcome to Ubuntu
    - expert-cws login
pyats:
  os: linux
  use_in_testbed: true
ui:
  group: Others
  icon: server
  label: DevNet Expert CWS
  label_prefix: cws-
  visible: true
  description: |-
    Cisco Certified DevNet Expert Candidate Workstation (Ubuntu 20.04)

    8 GB DRAM, 4 vCPU (can be adjusted)
```

Notice several differences from the CAT 8000V definition: **nature** is set to **server** rather than **router**, the **generator driver** is **ubuntu** instead of **csr1000v**, and the physical interfaces are named **ens3** through **ens6** rather than **GigabitEthernet1** through **GigabitEthernet26**. The **boot completed** strings also reference Ubuntu login prompts instead of IOS XE messages. Because Cisco already published this file with a unique **id**, **label**, and **description**, you do not need to edit any values before importing it.'



6. Save the file, then navigate to **Tools > Node and Image Definitions** to return to the node definitions overview page.

Notice the **Add** and **Import** buttons in the upper right corner. **Add** takes you to the dialog for creating a new node definition from scratch, in which case you need to provide details regarding virtualization, while **Import** loads an existing node definition file, such as the cws.yaml file you just reviewed.


7. To import the node definition, click **Import**, followed by **Choose a file...**, and then locate and open the **cws.yaml** file located in the **/Downloads/cml-images** directory.

8. Choose **Go to node definition**.
9. In the **General** section, find and expand the drop-down menu for **Available Image Definitions** to verify if any image definition is associated with this node definition.

Currently, no image definition is associated with this node definition.

You can create a node definition with no associated image definition, but you cannot do it the other way around.

10. After all changes are in place for the node definition, standard process is to move it to **Read Only** so no unexpected changes take place.

11. To view the node definitions overview, navigate to **Tools > Node and Image Definitions**.
12. Find your new CWS node definition and observe that it now appears in the list as its own distinct device type, grouped under **Others** with a label **DevNet Expert CWS**.

Congratulations, you have successfully imported a completely new node definition. To use the CWS in your labs, you still need to associate it with an image definition and upload the corresponding VM image, that process is covered in the next lab.
