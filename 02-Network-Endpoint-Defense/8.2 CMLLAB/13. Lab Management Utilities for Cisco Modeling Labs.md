

# Introduction

Lab Management Utilities are a set of software tools used to manage and control network labs. These utilities are designed to help you set up, configure, monitor, and test network equipment in a controlled lab or testing environment. This course will guide you through four activities, each designed to improve your knowledge of the Cisco Modeling Labs environment.

You will start with covering the fundamentals of importing and exporting lab topologies and progress all the way to using the power of REST API to effectively manage your lab environment.

In the four lab activities, you will perform the following:

- Import and export lab topologies.
    
- Use the Breakout Tool to access lab topologies.
    
- Manage labs through the REST API.
    
- Use the cmlutils library for lab management.

## Import and Export Lab Topologies

At some point, you will probably want to share your labs with others or do work in a lab that is already built. Fortunately, it is easy to export and import lab topologies and their configurations into Cisco Modeling Labs.


## Task 1: Importing Lab Topologies


While you will often create a lab topology from a "blank canvas," sometimes you may want to work on a lab that someone else created. Perhaps you are studying for Cisco CCNA, and you want to explore **spanning-tree root** bridge election in a hands-on lab environment. Instead of creating an interesting topology from scratch, you can import an existing lab topology to Cisco Modeling Labs.

To import a lab into Cisco Modeling Labs, you must have a YAML file that represents the lab. In this case, you already have the lab file saved on your local machine.

1. Open the file explorer on your Student VM to find a routing vlan topology file that was provided for you in the **/home/Downloads/Labs** directory.
2. Now try to import the provided lab file. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
3. In the upper-right corner of the dashboard is a blue button for **IMPORT**. Click the **IMPORT** button to open the **Import Lab** page.
4. From this page, you can access the lab topology files saved on your local machine to import them. Click the **paperclip** icon or the **File(s) to import** textbox to choose the lab file.
5. The file is in the **Downloads/Labs** folder on your local machine. Locate the provided **routing-vlan-lab.yaml** file and open it.
6. Click the **IMPORT** button and Cisco Modeling Labs will read the file and attempt to create a new lab for you on your server.

## Note

The import process might fail if the file is not a valid Cisco Modeling Labs file. This often happens if the lab was created in a different version of Cisco Modeling Labs, or if it uses nodes, images, or features that are not available on the Cisco Modeling Labs server to which it is being imported.


7. Open the imported lab topology by clicking the **GO TO LAB** button or by choosing it from the dashboard and observe the topology.

Now that you have learned how to import labs to **Cisco Modeling Labs**, you are probably wondering where you can find the topology files. Besides getting the topology file directly from the person who created the lab, there is a source directly from within Cisco Modeling Labs:

- **TOOLS / Sample Labs**: Accessible directly from Cisco Modeling Labs
    

The above library comes from Cisco Modeling Labs DevNet Community on GitHub and can also be accessed directly from your browser as well.

8. You can find some example lab files on Cisco Modeling Labs. Access the **TOOLS** menu by clicking it. Find and open the **Sample Labs** link.

9. Search "CCNA" at the top and pick a lab (or another available lab that interests you) and import it.
10. Cisco Modeling Labs will import the chosen lab and open its workbench.


## Task 2: Exporting Lab Topologies

Now you know how to import labs created by someone else to Cisco Modeling Labs. But what if you created a lab that you want to share with the world? Suppose that you created the lab named **My Lab Topology** running on this Cisco Modeling Labs server. In this task, you will export it to a YAML file that you can then share with others.


1. Go back to the dashboard and open the **My Lab Topology** lab.
2. Before you export a lab, it is a good idea to make sure the lab name and description will be helpful for anyone who later imports your lab.

Change the name of the lab and add a description.

- Lab Title: **Simple network topology**
    
- Lab Description: **Small LAN useful for exploring and testing basic network connectivity**

3. Expand the **LAB** menu from the toolbar on the top of your screen and click the **Download Lab** button to export the lab.

  
Cisco Modeling Labs uses the YAML data format for lab topology files. YAML is a common data format in the infrastructure as code space that is valued for its human readability. While easy to read, manually creating or making significant changes to a YAML lab file can be difficult to do without making syntax errors in the YAML formatting (that is, adding or removing spaces where needed). Typically, you create the topology in Cisco Modeling Labs and export it to YAML. However, making small changes is something that is useful and worth becoming comfortable with.


4. Before sharing this file with others, open it in a code editor and observe it.

Note that besides the topology-related information, the YAML file also includes the configuration for each node. This startup configuration is applied to the imported nodes.

When sharing labs, you often want to share your configuration as well. To do that, you must extract the running configuration from your devices and use it as the startup configuration shared in the lab file.

Try to change some configuration on the router and then extract it from the device.

5. Change some configuration on one of the devices and then try to include it in the lab YAML file. For example, change the IP address on the CAT 8000V node's GigabitEthernet1 interface to `192.168.1.254 255.255.255.0`

Open the CAT 8000V console and apply the following configuration.

```
cat8000v-0>enable
cat8000v-0#configure terminal
cat8000v-0(config)#interface GigabitEthernet1
cat8000v-0(config-if)#ip address 192.168.1.254 255.255.255.0
cat8000v-0(config-if)#end
cat8000v-0#
```


6. Before downloading the lab again, you must first extract the running configuration from the CAT8000V if you want to share it. Click the CAT8000V node and navigate to the **CONFIG** tab. Click the word **FETCH** and the running-config will be retrieved from the device.

7. After you click **FETCH**, then scroll down and verify that the new IP address has been retrieved and updated in the **CONFIG** tab.

8. Download the lab again and open the new YAML file. Observe the configuration for the cat8000v node.

Congratulations, now you know how to import and export lab topologies.
