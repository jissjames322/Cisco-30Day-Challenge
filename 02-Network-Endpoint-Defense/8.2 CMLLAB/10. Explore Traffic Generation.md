
## Scenario

The TRex node type is used for running Cisco's TRex traffic generator within a Cisco Modeling Labs lab. It is a powerful, open-source generator that offers capabilities provided by multiple commercial tools. TRex Stateless functionality includes support for multiple Layer 3 to Layer 7 traffic streams, the ability to change any packet field, and provides per stream or group statistics, latency, and jitter. The Advanced Stateful functionality includes support for emulating Layer 7 traffic with fully featured scalable TCP/UDP support. TRex can scale up to 200 Gb/sec with one server.


In this task, you will add the **TRex traffic generator** to your lab, connect to it using a **stateless GUI client, and verify the connectivity.**


1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. Make sure that your lab topology is loaded. Start the lab if needed.
3. Add one TRex node and one External Connector and drop them in your topology.

In Cisco Modeling Labs, the TRex mode is managed from a stateless client that needs management access to the TRex node. This access is provided by the external connector.

![[Pasted image 20261117135609.png]]


4. Connect the external connector to TRex eth0, TRex eth1 to PC1 eth0, and TRex eth2 to PC2 eth0.

In Cisco Modeling Labs, a TRex node must have between **two and three interfaces**. The **first interface is used for management access and should be connected to a bridge external connector node.** That interface IP address can be static or obtained over DHCP through the bridge external connector. An external GUI client can then connect to it.


5. Configure the external connector for the bridge mode and save the setting.

This environment does not use DHCP in the external bridge0 domain. You will configure a static IP address instead.

6. On your Student VM, open a terminal and verify the IP addressing.

7. From the Student VM, ping an IP address in the local subnet, such as 10.1.1.99 to check that it is free.

8. Go to the TRex configuration in your Cisco Modeling Labs lab, set the hostname to **TRex**, and the eth0 IP address to the validated free value. Do not change the default credentials.

You do not need to configure the IP addresses on the data interfaces. Traffic generators can source IP traffic from any IP address.

![[Pasted image 20261117140251.png]]


9. Start the lab. After a while, ping the TRex management IP address from your desktop VM to verify connectivity through the external connector.

10. From the terminal in the Student VM, start `trex-stateless-gui` located in the student home directory.

```
student@student-vm:~$ ./trex-stateless-gui &
```

## Note

The stateless client is preinstalled on the Student VM in the student home folder (/home/student). The client can be started in the background by appending the ampersand. If you need to install the client on another machine, download the stateless user interface for TRex from [https://github.com/cisco-system-traffic-generator/trex-stateless-gui](https://github.com/cisco-system-traffic-generator/trex-stateless-gui). Search for Builds. Ensure that the version that you download matches the TRex version running the TRex image in your lab.

11. In the TRex GUI, navigate to **File > Connect**, click **Show advanced options ...**, enter the TRex IP address and your username (cisco). Click **Connect**.
12. When connected, expand the network interfaces Port 0 and Port 1, and briefly familiarize yourself with the main options.

**Warning**: Do not confuse the ports displayed in the GUI with the TRex interfaces. The management interface (eth0) is not shown here at all. Port 0 represents the data interface eth1, Port 1 is eth2.

Acquiring a port is necessary for starting a traffic stream or testing connectivity. You will see a notification that the port was taken by cisco (your username for the TRex connection).

13. Choose **Port 0** and click **Acquire**. Do the same for **Port 1**.
14. For **Port 0**, choose the **Configuration** tab and compare the settings for a Layer 2 and a Layer 3 interface.

For Layer 2 operations, the source MAC address is obtained from the interface, but you need to provide the destination MAC address for the generated traffic. For Layer 3, you need to specify the source and destination IP address. You will use the Layer 3 option to ping the endpoints in your lab topology, PC1 (192.168.1.1) and PC2 (192.168.2.1).

15. For **Port 0**, choose **L3**, set the source IP to 192.168.1.2, the destination IP to 192.168.1.1 and click **Apply**. Enter the IP address to ping, 192.168.1.1, and click **Ping**.
