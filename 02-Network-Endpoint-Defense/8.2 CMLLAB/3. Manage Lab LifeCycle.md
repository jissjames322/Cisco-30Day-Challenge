
In this activity, You will run your lab for the first time. You will learn how to start, stop, wipe, delete nodes, and gain a brief understanding of what is happening on the Cisco Modeling Labs server. You will also explore the capabilities of the Autostart and Node Staging features.

Building an entire lab, making connections between nodes, and configuring them is of no use if you do not power on the devices. Knowing how to start, stop, and delete labs is a vital part of Cisco Modeling Labs.

1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. On the **Dashboard**, locate **My First Lab Topology** and open it.
3. Click **LAB** in the toolbar and select **Start Lab.**

Notice that the node icons in the topology will change as the lab starts.

The following is a brief node state explanation:

- No icon: Node stopped.
    
- Grey clock icon: Node start request queued.
    
- Green arrows icon: Node started.
    
- Green check icon: Node booted.

## Note

A gray clock icon means CML cannot start the node because doing so would push the server beyond its CPU or memory limit — free up resources by stopping other running nodes.

4. Wait a few minutes and confirm a green check mark appears next to all nodes.
5. Next, go to the **LAB** tab and click **Stop Lab**.
6. Wait for the nodes to become gray.

Keep in mind that stopping a lab is much faster than starting one. Until a node is started, no actual resources are allocated on the Cisco Modeling Labs server for it. No virtual disk drive, no virtual interface, or MAC addresses are created and assigned. These resources make up the virtual machine that represents the node in your topology.

When a node starts up, either individually or as part of an entire lab, a virtual machine instance is created with all required resources. When you stop a lab or node, Cisco Modeling Labs powers down the virtual machine, but keeps the virtual machine created and ready to be started back up.

This is very handy because any configurations or changes made to a started node are not lost when you power down a lab. Remember that Cisco Modeling Labs creates a virtual machine for each node as it is started, and that virtual machine is saved, even when a node is stopped.

7. It is also possible to start and stop individual nodes. To do so, click **PC1** and click **START** in the pop-up window.
8. Observe how **PC1** transitions to the active state. When **PC1** is ready, a green check mark appears next to it.
9. Start all nodes in your topology and wait until a green check mark appears next to all of them. This can take a few minutes.
10. To wipe an individual node, you must first stop the node. Right-click **PC1** and click **Stop**.


Wiping a node refers to erasing all the resources linked to that node.

Wiping completely erases any configuration and resources that were associated with the node from the CML server. The next time you start the node, it will start off fresh, generating a new MAC address and any other resources needed to run the node. As there is no prior state remaining on a wiped node, it will load the initial configuration, known as the "bootstrap" configuration.

11. To wipe the node, right-click PC1 and choose **Wipe**.

## Note

The gray X has disappeared from the node. This is how you know the difference between a node with a virtual machine built and ready to be restarted, and one without.

12. To wipe all nodes at once, deselect all nodes and click **LAB** in the toolbar. Proceed by stopping the entire lab by clicking **Stop Lab**.
13. Under **LAB** in the toolbar, click **Wipe Lab**.
14. In the **Wipe lab?** pop-up window, click **OK.**
15. Now that the nodes are wiped, you can delete them. To delete a node, right-click it and choose **Delete**. (Do not actually delete any nodes.)
