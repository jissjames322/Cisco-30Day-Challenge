
Cisco Modeling Labs includes a **built-in console** which provides CLI-based access to consoles of network nodes running in a topology and GUI access using **VNC**. The CLI is essential for configuring routers, monitoring network status, and diagnosing connectivity issues, offering direct interaction with network nodes. In this activity, you will review the basics of using the CLI console. You will consider how to access the CLI console of nodes, how to access the GUI console of nodes, and how to use basic CLI console commands.


# Access Node Consoles

The console of a node refers to a physical or virtual port that allows direct, out-of-band (OOB) access to the node configuration and enables you to monitor and troubleshoot. In this activity, you will review where to find the console and how to use it.


1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. On the **Dashboard**, locate **My First Lab Topology** and open it.
3. Make sure that your lab is running. If it is not running, start the lab.
4. Right-click the **Router** node and choose **Console** in the drop-down menu.
5. You should notice the **Routers** console tab opening in the bottom pane. Go ahead and click **OPEN CONSOLE**.
6. To begin interacting with the console, click your mouse in the console window and press enter a few times until you are presented with the user prompt for the node.

You have now gained access to the console. Now you can verify that your network was correctly configured.

7. To determine if your devices recognize each other, enter the `show cdp neighbors` command in the console window and press **Enter**.

8. Go ahead and close the **Routers** console by clicking the **exit button** found in the upper left side of the pane.

## Note

If you right-click the Node name instead of closing it with the red ‘X’, you can change your console font settings. Keep in mind these settings are global and not per node.

9. In the same manner as you did for the **Router,** open the console for **Switch1**.
10. Check the MAC address table using the `show mac address-table` command.

You can change the running configuration of nodes from the console.

11. In the console, use the `enable` command to enter privileged EXEC mode.
12. Use the `configure terminal` command to enter global configuration mode.

From here, create the password **cisco** for entering Switch1 privileged EXEC mode.

13. In the console, enter the `enable secret cisco` command.

Go ahead and explore. Try accessing the console of Switch2 and try out some other commands.

14. Open the **PC1** console. To gain access, use the username **cisco** and password **cisco**.


15. Try reaching PC2 using the `ping 192.168.1.10` command.

16. Try reaching the router using the `ping 192.168.2.1` command.

VNC, also known as Virtual Network Computing, is a Remote Desktop Protocol that allows users to control and interact with a computer in a GUI remotely over a network. It is used to connect to the GUI for nodes that include one like the Desktop node.

17. Next, right-click **PC2,** choose **Vnc** in the drop-down menu and open the VNC connection in the pane window.

18. In the drop-down menu, log in using username **cisco** and password **cisco**. 

19. Open the **Terminal Emulator** located on the taskbar of the **Desktop**.
20. Try pinging PC1 using the `ping 192.168.2.10` command.

You can explore the **Desktop** environment further.

The Desktop node included with Cisco Modeling Labs has a terminal application, web browser, and other basic Linux utilities installed.


## Note

My First Lab Topology does not have external connectivity configured to provide internet access to the client nodes.


Congratulations! After finishing this course, you should feel confident connecting to the CLI console and VNC from different nodes and diagnosing basic configurations.
