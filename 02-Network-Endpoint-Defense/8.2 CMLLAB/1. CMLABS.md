
# Explore Cisco Modeling Labs Basics


Cisco Modeling Labs is a powerful networking tool that lets you quickly and easily create and run virtual networks that can often replace real-life physical lab environments, which are more expensive and time-consuming to set up and run. **Using Cisco Modeling Labs, you can build labs to learn and explore different network protocols and test configuration changes, without the need to purchase and install any physical gear.**

With Cisco Modeling Labs, you can add the devices that you want to use, add links between the interfaces, and start the lab using only a simple WebUI that you access with your browser.


### Step 1

Access the Cisco Modeling Labs WebUI using the Chrome browser to explore an example lab simulation.

### Step 2


Log in using the credentials, username &  password

When you are logged in, you will be presented with the Dashboard page, which provides access to all existing labs. In this case, there already is a running lab simulation named Example Lab.

### Step 3 

Open the **Example Lab** simulation by clicking it and explore the topology.

In lab simulations, you can use multiple Cisco and third-party devices that behave just like they would in a real-life network.


The Cisco Modeling Labs license provides you with various Cisco devices that run the same network operating system that is running on your physical gear, but is designed to work on virtual machines:

- IOL / IOL-Layer2 (IOS on Linux)
    
- Catalyst 9800-CL
    
- IOS XR 9000v
    
- NX-OS 9000v
    
- FTDv/FMCv
    
- CAT 8000v
    
- IOSv and IOSvL2

Besides the Cisco images, Cisco Modeling Labs also provides you with open-source virtual machine images that can be used for host devices in your lab topology. Some of the available device types are also meant to be used as different networking tools, such as traffic generators:


- Server (Tiny Core Linux)
    
- Alpine Linux (GUI based and CLI based)
    
- Ubuntu
    
- Trex

## Note

The Unmanaged Switch and External Connector nodes do not count toward the total licensed node limit.

The images provided with the Cisco Modeling Labs license are sometimes referred to as "reference platforms" and can be added to Cisco Modeling Labs during the installation process.

Besides the reference platform images, Cisco Modeling Labs also allow you to add other Cisco operating systems and third-party VM images.

### Step 4

Observe all the available images by clicking the **TOOLS** button in the upper-right corner and choosing **Node and Image Definitions**.


Using different Cisco and non-Cisco devices, you can quickly build useful hands-on lab environments. Once you start the simulation, you can interact with the devices just like you would in a physical lab—by accessing the CLI or the GUI directly from Cisco Modeling Labs.


### Step 5

Try to access the CLI on the CAT8000V node by right-clicking it and choosing the **Console** option from the drop-down menu.

The console panel will open at the bottom of the window. Click **Console** to connect the Cisco Modeling Labs web application to the serial console for the node.

### Step 6

Using that interface, you can configure the CAT 8000V node just like you would configure the physical router. Try executing a couple of commands.

To interact with the console, click inside the console window and click **Enter** a few times. You should be presented with the user prompt for the node.

```shell
cat8000v-0>enable 
cat8000v-0#show version
```
### Step 7

Similarly, you can access the GUI of the Desktop node, which runs Alpine Linux. Right-click one of the desktops and choose **VNC** (Virtual Network Computing) from the drop-down menu.

A new Desktop tab should be added to the bottom pane. Click the **Open VNC** button in that tab. The username and password are both set to "......"

### Step 8

Open the CAT8000V router console again and `ping` the PC with the IP address 192.168.1.10.

The IP address of the desktop-1 device is **192.168.1.10**.


```shell
ping 192.168.1.10
```

### Step 9

The ping fails because the devices aren't set up correctly yet. Even though everything else is already configured, **the router's interface is currently down. Bring up the interface (GigabitEthernet1) and try to ping the PC again.**

```shell
cat8000v-0#configure terminal
cat8000v-0(config)#interface GigabitEthernet1
cat8000v-0(config-if)#no shutdown
cat8000v-0(config-if)#end
```

This time the ping should be successful.

# Cisco Modeling Labs Architecture


**Cisco Modeling Labs is designed and built on top of a REST-based API that exposes all the functionalities. Each operation that can be done from the Cisco Modeling Labs user interface, for example, adding nodes, creating links, or starting the simulation, is powered by the API. All other user-facing interfaces use the API to perform different operations.**

You can also use that same API directly and manage the complete lab lifecycle programmatically. To help you integrate Cisco Modeling Labs in your automated workflows, there is also a **Python client library that you can use to create and manage the lab simulations.**

To perform the operations, the **API uses the controller that is responsible for deploying virtual devices and providing all the information about the lab simulations**. All the devices are deployed on available compute instances, using memory and CPU resources. The number of compute nodes depends on the type of the deployment. Cisco Modeling Labs can be deployed as a **standalone solution where everything runs on the same server or virtual machine. It can also be deployed as a cluster, where multiple servers are bundled together, and the controller can use the resources on each of them.**

## HTML5 User Interface

## REST API

All the actions that can be performed in the user interface use the underlying REST API. The API can also be used directly, meaning that anything that you can do in the user interface, you can also do programmatically. You can use your custom applications to manage the lab simulations through the API and include Cisco Modeling Labs in your NetDevOps operations.

The API is documented with a Swagger user interface, running directly on the Cisco Modeling Labs server.
