## Scenario

Cisco Modeling Labs is a great tool for exploring network technologies. **Whenever you dive into network operations, you may have to capture and analyze traffic exchanged between the nodes.** You will use the **packet capture and analysis feature to inspect ICMP and Spanning Tree Protocol (STP) packets on a link.**


## Task 1: Capture Traffic Using CML User Interface

In this task, you will capture all traffic that goes through a link, without any fine-tuning.

1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. Make sure that your basic topology is loaded. Start the lab if needed.
3. Right-click PC1 and open its console. Log in with the username **cisco** and password **cisco**. Verify the PC1 addressing using the `ip addr` command.
4. From PC1, ping the router (10.0.1.254) and keep the ping running.
5. Right-click the link between Switch1 and the Router. Choose **Packet Capture**.
6. Click **Start**.

You can currently only have one packet capture per link. When you want to start a new capture, you can save the previous results by downloading the PCAP file to your computer.

7. After a while, you should see the captured packet counter increasing. Click **STOP**.
8. Choose one of the captured ICMP packets. The lower pane will allow you to analyze the packet. Expand the headers and inspect the available information.

**When you download the captured packets to your local machine as a PCAP file, you can examine them using a packet analysis tool, such as Wireshark**. The **PCAP** is a widely used file format that was developed in **parallel to the tcpdump and libpcap libraries.** PCAP files are easily read by various tools and software programs.

## Customize Traffic Capture

You will selectively capture STP traffic and fine-tune the capture behavior. The following settings allow you to control the capture parameters:

- **Max Packets** is the number of packets to capture. Capture will continue on the link until this number of packets have been captured.
- **Max Time** is the length of time, in seconds, to capture packets. Capture will continue on the link until this many seconds have elapsed.
- A **Berkeley Packet Filter (BPF)** can be applied to restrict which packets are captured. Cisco Modeling Labs will only capture the packets that match this filter. If you set both the max packets and a BPF, only the packets that match this filter will count toward the max packets limit.
- BPF templates include a list of several predefined templates to get you started with customizing the BPF setting.

9. Click **Settings**.
10. Set the maximum capture time to 200 seconds and choose a filter to capture only Spanning Tree packets. Click **Apply**.

Starting with Cisco Modeling Labs 2.9 the capability was introduced to capture different Encapsulation protocol types. This includes Frame Relay, PPP/PPPoE, Cisco HDLC, SLIP, X.25. At the same time this feature was introduced, a new node type was added IOL (Serial) which will allow you to build legacy routing labs where you might need to capture non-Ethernet traffic.


## Note

The Berkeley Packet Filter (BPF) is a solution designed, among other things, for network traffic analysis. The BPF syntax is explained at [https://www.tcpdump.org/manpages/pcap-filter.7.html](https://www.tcpdump.org/manpages/pcap-filter.7.html). An overview with some examples can be found at [https://www.ibm.com/docs/en/qsip/7.5?topic=queries-berkeley-packet-filters](https://www.ibm.com/docs/en/qsip/7.5?topic=queries-berkeley-packet-filters).


11. Start the capture. When the STP packets have been detected, choose one of them and examine the details by expanding the appropriate headers.


## Task 2: Packet Capture Streaming

You have learned how to perform a packet capture directly within the Cisco Modeling Labs workbench, and also how to filter that capture so that you only see what traffic interests you. We are now going to look at a new feature that was introduced in version 2.10, which is Packet Capture Streaming. **The benefit that comes from this option is that you do not have to worry about transferring the PCAP file into your local Wireshark instance.** You apply your own pre-saved filters directly within Wireshark; on the traffic passing inside Cisco Modeling Labs.


12. Log into the Breakout UI using the Chrome browser bookmark or go to http://127.0.0.1:8080

## Note

The Breakout tool was pre-installed for you in this environment, and set to start as a service. Setting up the Breakout tool would be a required step in your own deployment. The tool runs on Windows, Mac, or Linux. For more information vist: https://developer.cisco.com/docs/modeling-labs/breakout-tool-overview/.

13. Click the CAPTURES tab and observe that no packet captures are currently running.
14. Open an additional browser tab and log in to the Cisco Modeling Labs WebUI.
15. Right-click the link between Switch1 and the Router. Choose Packet Capture.
16. Click Start in the Nodes pane towards the bottom.
17. Switch back to your Breakout UI browser window, make sure you are on the **CAPTURES** tab. Click **Refresh** and you should notice the stream appear.
18. Click the blue magnifying glass icon the right. Wireshark will automatically launch for you. At that point you should begin to see packets appearing in your local Wireshark from the CML lab packet capture.

Congratulations that completes this lab training. You learned about performing a packet capture directly inside CML. In addition, you learned how to properly filter or customize the traffic captured off the network, and how to stream the packets being captured directly into your Wireshare instance.
