
## Scenario

Cisco Modeling Labs is an amazing tool for exploring network technologies. Suppose you need to emulate real-world WAN conditions in your lab. Starting with Cisco Modeling Labs 2.6, you can do that using the native link conditioning feature, configured directly on any link in your topology. First, you will manually configure the link conditioning parameters on each WAN link and watch the resulting traffic patterns using extended ping. Then, you will use the IP service-level agreement (SLA) feature on the branch routers to monitor the link delay and fine-tune the link conditioning settings to model different WAN profiles.

## Task 2: Configure Link Conditioning on the WAN Links

The limitation of the existing lab setup is that the WAN links are not conditioned using realistic WAN characteristics. In this scenario, you need to simulate different packet loss and delay values on the two links. To reflect real-world WAN parameters, you will configure the Cisco Modeling Labs built-in link conditioning feature directly on each WAN link, without changing the topology.

Link conditioning supports the following characteristics:

- **Bandwidth**: the throughput limit for the link.
- **Latency**: the one-way delay applied to the link, with an optional amount of **Jitter**. Because the delay applies independently in each direction, the round-trip time (RTT) you observe is roughly double the configured value.
- **Loss**: the percentage of packets dropped on the link.
- **Enable**: a toggle to turn the conditioning on or off without deleting your settings.

8. Select the WAN link between HQ and BR1 in the Workbench.

```
The Link Conditioning settings appear at the bottom of the pane, underneath Link Statistics.

```

9. Set the **Bandwidth** to 1024 kbps and **Latency** to 20ms, then turn on the **Enable** toggle to apply the settings to this link.
10. Select the WAN link between HQ and BR2. Set the **Latency** to 200 ms, increase the **Loss** to 20 percent, and turn on the **Enable** toggle.

## Note

Keep in mind that a 20 percent loss rate applies independently to packets crossing the link in each direction. Because an ICMP echo request and its echo reply each cross the link once, the effective round-trip loss rate is roughly 40 percent.

## Task 3: Verify Link Conditioning Using IP SLA

Extended ping does not really offer any information about the delay experienced on the link. You will use the IP SLA feature to monitor the delay. IP SLA is an active method of monitoring and reliably reporting on network performance.

12. Stop and start the Branch routers BR1 and BR2. The restart may take a few minutes.

Right click each device inside the Workbench and choose **STOP** then **START**.

13. Open the router consoles and enter the privileged mode.
14. On BR1, configure an SLA based on ICMP echo requests to HQ (10.0.1.254), sent every 5 seconds. Start the SLA probe immediately.

```
BR1# configure terminal
BR1(config)# ip sla 1
BR1(config-ip-sla)# icmp-echo 10.0.1.254
BR1(config-ip-sla-echo)# frequency 5
BR1(config-ip-sla-echo)# exit
BR1(config)# ip sla schedule 1 start-time now
```

15. On BR2, configure the same SLA probe, except for the HQ IP address (10.0.2.254).

```
BR2# configure terminal
BR2(config)# ip sla 1
BR2(config-ip-sla)# icmp-echo 10.0.2.254
BR2(config-ip-sla-echo)# frequency 5
BR2(config-ip-sla-echo)# exit
BR2(config)# ip sla schedule 1 start-time now
```

16. After a few seconds, exit from the configuration mode on both branch routers and verify the SLA results.

The SLA summary on BR1 should resemble this output:

```
BR1# show ip sla summary
IPSLAs Latest Operation Summary
Codes: * active, ^ inactive, ~ pending

ID           Type        Destination       Stats       Return      Last
                                           (ms)        Code        Run
-----------------------------------------------------------------------
*1           icmp-echo   10.0.1.254        RTT=42       OK          3 seconds ago
```

The SLA summary on BR2 should resemble this output:

```
BR2# show ip sla summary
IPSLAs Latest Operation Summary
Codes: * active, ^ inactive, ~ pending

ID           Type        Destination       Stats       Return      Last
                                           (ms)        Code        Run
-----------------------------------------------------------------------
*1           icmp-echo   10.0.2.254        RTT=401     OK          1 second ago
```

Can you explain why the round-trip times (RTTs) differ so significantly between the two links?

The **Latency** field in the link conditioning settings represents a one-way delay, and an ICMP echo request and its echo reply each cross the link once, so the RTT reported by the SLA probe is roughly double the configured value. Because you used a much lower **Latency** value on the HQ-BR1 link, its RTT stays closer to the lab's baseline. The HQ-BR2 link, however, was explicitly conditioned with a 200-ms **Latency**, so the SLA probe reports an RTT of roughly 400 ms.


## Task 4: Model Different WAN Profiles Using Link Conditioning


So far, you configured each WAN link's bandwidth, latency, and loss values individually to model a high-quality and a lower-quality link. In this task, you will fine-tune those settings further to model two common WAN profiles, and watch the results in the SLA probes.


17. Select the HQ-BR1 link again and update the link conditioning settings to a **Bandwidth** of 100000 kbps and a **Latency** of 160 ms. Click **Apply** when complete.
18. Select the HQ-BR2 link and update the link conditioning settings to a **Bandwidth** of 250 kbps, a **Latency** of 600 ms, and a **Loss** of 1.5 percent.
19. After a few seconds, compare the SLA results on both branches. This verification completes the lab activity.

## Note

If you do not get fresh SLA results (not older than 5 seconds), delete the SLA probe and configure it again using the commands provided in the earlier steps.

The round-trip times should reflect double the configured **Latency** on each link profile: roughly 320-ms RTT in the WAN (unlimited) profile and roughly 1200-ms RTT in the EDGE (good) profile.

## Note

The SLA results can be used as an input to various features, such as static routing or policy-based routing (PBR). In contrast, dynamic routing protocols, such as EIGRP, do not reflect the actual link parameters in the advertised metric (composite metric in the case of EIGRP).
