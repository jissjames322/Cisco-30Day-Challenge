
In this activity, you will explore the default startup configurations of **My First Lab Topology**. You will consider the current configuration of nodes, how to change the node hostnames, and do some basic configuration changes. You will also explore nodes with multiple configuration files.

The real satisfaction in Cisco Modeling Labs begins with making changes to node configurations. In this activity, you will consider exactly that. You will start this activity by changing the hostnames of the nodes.

1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. On the Dashboard, locate **My First Lab Topology** and open it. Make sure that the nodes are stopped and wiped.


Before you can make any startup configuration changes to nodes, they must be stopped and wiped. Make sure that has been done.

The lab should already be in the correct state but to be certain, click the **LAB** tab and click **Stop Lab**, then repeat and click **Wipe Lab**.

3. Click **Switch1** and choose **CONFIG** in the pop-up window tabs.

This is the startup-config for your switch. Changes here are applied upon boot, and as you will see later in this lab some devices have multiple configuration files.

4. Change the hostname to **Switch1** and save the changes.
5. Go ahead and change the hostname for **Switch2** to **"Switch2"** and for the **Router** to **Router1**.


In the **CONFIG** tab, you can change or add any additional startup configurations to the default configuration to have your lab start already preconfigured and functional. In addition to hostnames, you can also create local admin users, configure VLANs, configure interfaces, and perform activities such as routing.

6. Proceed by changing the hostnames of **PC1** to **"PC1"** and **PC2** to **"PC2"**.

All your nodes now have configured hostnames. When building labs, always remember to give nodes unique hostnames.

You will also be making some basic changes to nodes configurations.

7. Click **Router1** and open the **CONFIG** tab. Add the following configuration for both interfaces under the hostname as shown below:

```shell
interface GigabitEthernet0/0
no shutdown
ip address 192.168.2.1 255.255.255.0

interface GigabitEthernet0/1
no shutdown 
ip address 192.168.1.1 255.255.255.0
```

8. Open the **CONFIG** tab of **PC1**. Add the configuration for **PC1**:

```shell
ip address add 192.168.2.10/24 dev eth0

sudo ip route add default via 192.168.2.1
```

9. Open the **CONFIG** tab of **PC2**. Add the configuration for **PC2**:

```shell
ip address add 192.168.1.10/24 dev eth0

sudo ip route add default via 192.168.1.1
```

Great job! All the nodes now have basic network configurations done.

Every node you configured in this lab used a single startup configuration file. Some node types use more than one. To see the difference, you will add an Ubuntu node and explore its configuration files.

10. Click Add Nodes at the top of the workbench and add an Ubuntu node to toplogy.
11. Click the Ubuntu node and choose the CONFIG tab. Locate the Configuration File dropdown.

For most nodes, such as switches, routers, and simple Linux hosts, the CONFIG tab shows a single configuration and no dropdown. The Ubuntu node supports multiple configuration files, a Configuration File dropdown appears at the top of the pane.

12. Click the Configuration File dropdown and select each file ( user-data / network-config ) to view its contents.

Selecting a file changes only which file appears in the text area for viewing or editing. The text area updates to show the contents of the file you select. Each file’s configuration serves a different purpose for the node.

## Note

A node selects its configuration file by filename, and that filename is hard-coded into the node's image. Selecting a different file from the dropdown changes only which file you are editing. It does not change which file the node reads at startup. For this reason, edit the existing files rather than renaming them or adding new ones.


Congratulations! You are now familiar with making changes to node hostnames and basic configurations, and you have seen how Cisco Modeling Labs handles nodes that use multiple startup configuration files.
