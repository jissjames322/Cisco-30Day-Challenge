## Task 1: Work with Image Definitions


Sometimes, you may want to use software versions in your Cisco Modeling Labs topologies that are not part of the reference platform. Perhaps you are running a different version of CAT 8000V in your production network, and you want to use that exact version in Cisco Modeling Labs as well. To do this, you can import your version of the image to Cisco Modeling Labs and connect it with an existing node definition. You can either connect it with a default node or a node you imported. In this lab, you will learn how to work with image definitions.

1. Log in to the Cisco Modeling Labs WebUI using the Chrome browser.
2. From the **Dashboard**, navigate to **Tools > Node and Image Definitions**.
3. At the top of the screen, choose **Image Definitions**.
4. Choose an existing CAT 8000V image definition for review.

The **Image Definition** overview lets you inspect all current image definitions, review or modify them, and add new ones. Specifically, note that this image definition is set to **Read Only**, restricting modifications. Those with admin privileges can alter this, but not every field is amendable. The **Disk Image** (indicating the VM filename) and **Node Definition** (showing the linked node definition) fields are very important.

5. At the top of the window, choose **Back** and click **Image Definitions** to return to the image definitions overview list.

Observe the **Add** and **Manage** buttons in the upper right corner. The **Add** button takes you straight to the new image definition dialog, while the **Manage** button allows you to upload the image file or image files first. By default, there are no unassociated image files, so even if you try to create a new image definition, you will fail, because an image must be uploaded first.

6. In the upper-right corner, click **Manage**.
7. Click **Choose a file...** in the file selector dialog, and pick a file with either the .qcow or .qcow2 extension.
In this case, a CAT 8000V image is already downloaded and stored on your Student PC. You can find it in the **cml-images** folder.

## Note

By default, Cisco Modeling Labs comes bundled with a set of reference images, however, not all Cisco images are included. For additional Cisco and third-party device YAML definition files, see [https://github.com/CiscoDevNet/cml-community](https://github.com/CiscoDevNet/cml-community)


8. With the file selected, choose **Upload Image** to transfer the desired file into the Cisco Modeling Labs.

Once complete, inside the **Uploaded Images** panel click **Create new image definition**.

9. Note the required fields in the **Image Definition Editor**.

10. Fill in the **ID**, **Label** and **Description** fields, choose the available **Disk Image** (you should see the one you just uploaded) and the corresponding **Node Definition**.

You do not need to enter or modify the **Linux Native Simulation** fields. For **ID**, **Label**, and **Description**, you can use any values that you like.

Choose the available **Disk Image** from the **Disk Images** section.

11. Choose **Create Image Definition** at the bottom of the page.
12. Observe the newly created image definition.

The newly created image definition is not **Read Only** by default, enabling you to edit or delete it if necessary.



13. Return to the image definition overview list by navigating to **Tools > Node and Image Definitions > Image Definitions**.


Congratulations, you have successfully created a new image definition. If you return to Step 6 and observe the list of **Uploaded Images**, the list should be empty. The reason for this is because the image you uploaded is now associated to the image definition you created and therefore not available for further use. If you want to create another image definition, you need to upload another VM image or delete your image definition. In this case, the previously uploaded file will become available again.


## Note

Alternatively, the VM image can be uploaded to the Cisco Modeling Labs server using SCP, accepted on the regular port 22 exclusively for uploading VM images. Use the credentials that you employ to access the Cisco Modeling Labs user interface. For instance, log in as the **admin** user (not the **sysadmin** user). Given that the SCP connection is limited to image file uploads, indicate the root folder as the destination for the SCP command.

The following is an example using a Cisco Modeling Labs server at 172.16.0.10 and transferring an FTDv 7.7 .qcow2 file:

- `scp cisco-secure-ftdv-7-7-0-80.qcow2 admin@172.16.0.10:/`


# Summary

In addition to the built-in reference platforms, Cisco Modeling Labs also supports a "bring your own image" model, facilitating the integration of any KVM-supported images. While Cisco and the community can provide example YAML files for third-party node and image definitions, the actual QCOW image files require appropriate licensing and permission from the respective platform owners. Users must provide them themselves based on their own licensing agreement. You can, however, access and use the Cisco Modeling Labs YAML file definitions, which have been established to support various platforms, both from Cisco and other third-party vendors.

- The Node Definitions folder, located at [https://github.com/CiscoDevNet/cml-community/blob/master/node-definitions](https://github.com/CiscoDevNet/cml-community/blob/master/node-definitions), contains the YAML file definitions for a Cisco Modeling Labs node. The VM configuration details are included in the YAML file, such as CPU, RAM, network adapters, and so on.
    
- The Virl Base Images folder, located at [https://github.com/CiscoDevNet/cml-community/blob/master/virl-base-images](https://github.com/CiscoDevNet/cml-community/blob/master/virl-base-images), contains a folder for each added platform disk image. Within each platform folder, you will find a YAML file that references a specific disk_image file for the platform.
    

## Note

You will need to download the disk images from the vendors yourself.
