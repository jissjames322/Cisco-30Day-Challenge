# What Exactly are AI and ML?


Artificial Intelligence (AI) is an umbrella term that can be explained as the simulation of human intelligence by computer systems. These processes include learning, reasoning, and self-correction.

![[Pasted image 20261026000135.png]]

Machine Learning (ML) is a method that enables machines to mimic intelligent human behavior by learning from data without being explicitly programmed. This method allows computer systems to self-improve their performance on tasks such as visual recognition, natural language understanding, and physical actions through data analysis and pattern recognition.

![[Pasted image 20261026000228.png]]

Unlike traditional programming, which requires specific instructions, machine learning uses data (for example, images, texts, or numerical data) to train models to make predictions or identify patterns, improving over time with more data and adjustments. This approach can lead to systems capable of descriptive, predictive, or prescriptive functions, offering insights, forecasts, or action recommendations based on the analyzed data.

# How AI Learns

In the realm of Machine Learning (ML), there are various approaches through which algorithms can learn and improve.

Supervised Learning

Supervised learning is a method where the AI system is trained using labeled datasets. For example, in network security, supervised machine learning is utilized to categorize network traffic or predict security threats by training AI systems with datasets that have already been tagged with outcomes, such as "safe" or "malicious" traffic. These AI systems learn from the labeled data, identifying patterns and relationships between different types of network activities. The process involves feeding the algorithm both the data it needs to analyze (inputs) and the expected outcomes (outputs) to teach it what to look for.

![[Pasted image 20261026000441.png]]


Unsupervised Learning

Unsupervised learning does not rely on pre-labeled data. Instead, the algorithm is given the freedom to sift through the data and uncover patterns or groupings by itself, like a detective piecing together clues without a case file. This method is particularly useful in networking for the purpose of anomaly detection. It enables the system to spot unusual traffic patterns that deviate from what's considered normal, potentially flagging a security breach without prior knowledge of what to look for.

![[Pasted image 20261026000905.png]]

Reinforcement Learning

Reinforcement learning stands out as a dynamic learning process where the AI system learns from the consequences of its actions, akin to a trial-and-error learning method. In the context of network operations, this means the system can refine network performance by adjusting configurations and policies in response to real-time feedback, aiming to achieve optimal performance. This approach allows network systems to adaptively manage and optimize their operations.

# Application of AI and ML in Network Operations

AI and ML are revolutionizing network operations by enhancing efficiency, reliability, and security, transitioning from reactive to proactive management. The following are areas that benefited the most from this transformation.

![[Pasted image 20261026001033.png]]

Predictive Maintenance

A significant application of AI and ML in network operations is predictive maintenance, where AI algorithms analyze data from network equipment to forecast potential failures before they happen. This proactive approach not only minimizes downtime but also prolongs the lifespan of network hardware by allowing for timely preventive maintenance.

Anomaly Detection and Security

Another critical area is anomaly detection and security. ML models are capable of continuously monitoring network traffic in real-time, identifying deviations that could signify security threats, such as distributed denial of services (DDoS) attacks, malware, or unauthorized access attempts. By understanding the characteristics of normal traffic, these models can swiftly detect and alert people to suspicious activities, enabling a quick response to mitigate potential threats.

Traffic Analysis and Management

AI also plays a pivotal role in traffic analysis and management. By examining traffic patterns and forecasting future congestion points, AI-driven solutions can dynamically modify routing protocols and allocate bandwidth more efficiently. This ensures that the network operates smoothly, maintaining high performance and quality of service for users.

Automated Configuration and Management of Network Settings

Furthermore, AI and ML facilitate automated configuration and management of network settings, streamlining routine tasks, significantly reducing the likelihood of human error. These intelligent systems can autonomously configure network devices, apply updates, and adjust settings in real-time according to evolving network demands and conditions.

Root Cause Analysis

Lastly, AI aids in root cause analysis, a process traditionally marked by its time-consuming nature. By analyzing data across various network elements, AI can swiftly pinpoint potential problems, accelerating the troubleshooting process and consequently reduce network downtime.

# Types of AI: Predictive and Generative


Predictive AI refers to artificial intelligence applications that analyze historical data to forecast future outcomes. It relies on machine learning algorithms to identify patterns and trends within vast datasets, enabling it to make educated predictions about future events. In the context of network engineering, predictive AI can significantly enhance network performance, reliability, and security by anticipating problems before they arise and allows for proactive management.

Generative AI goes beyond prediction to create novel insights, employing sophisticated machine learning models like Generative Adversarial Networks (GANs) and transformer models. # Using LLMs — No Wrong Answers, Just Wrong Questions


When interacting with LLMs like ChatGPT, the way you phrase your questions plays a crucial role in the quality and relevance of the responses you receive. This is a consequence of how LLMs process and understand language. Essentially, LLMs analyze the "distance" between words within the vast landscape of their trained data, determining their relationships and context to generate appropriate responses. For instance, the words "apple" and "fruit" are close together, whereas "car" is placed further away from either "apple" and "fruit." This means that the word "apple" is more likely to be associated with the word "fruit" than with the word "car."

![[Pasted image 20261026001633.png]]


Vocabulary becomes a critical tool in this interaction. Precise and clear language can significantly narrow down the scope of the query, guiding the LLM to understand the exact nature of the information or assistance you're seeking. Conversely, vague, or ambiguous questions can lead the model to interpret the request in a broader context than intended, resulting in answers that might not be as specific or helpful as you hoped.

# Using LLMs — Minimize Inaccurate Responses


Sometimes, no matter how hard you try to provide accurate and descriptive information in the prompt, you will get incorrect, or even fictional information that the model represents as fact, a phenomenon known as hallucination. This occurs due to the model's reliance on patterns in the training data rather than factual accuracy. The training data itself might even be obsolete since it is very time and resource consuming to re-train a model with an updated dataset.
![[Pasted image 20261026001950.png]]

Retrieval-Augmented Generation (RAG) is a technique that helps alleviate the issue of hallucination and out-of-date answers in LLMs. RAG combines the capabilities of a retrieval system and a generative model. When given a prompt, the retrieval system first fetches relevant documents or pieces of information from a large database or knowledge source. Then, the generative model uses this retrieved information to generate a response. This process ensures that the responses are grounded in the retrieved documents, which can help improve factual accuracy and reduce the likelihood of hallucination. The key advantage of RAG is that it anchors the model's responses to real-world information contained in the retrieved documents, making the responses more accurate and less prone to fabricating information.


![[Pasted image 20261026002055.png]]

This capability makes RAG systems particularly valuable for navigating complex technical documentation. Instead of manually sifting through dense material, users can rely on the RAG system to extract relevant details and present them in a digestible format. This not only speeds up the process of finding information but also ensures that the guidance provided is accurate and directly relevant to the task at hand, as it's grounded in the actual content of the documentation. You can leverage your own RAG system with most modern LLMs by simply drag-and-dropping a PDF document into the prompt and directing the LLM to consult the documentation when giving you the response. ChatGPT, Claude, and Gemini all support file uploads. For example, you can upload the PDF manual of Cisco Nexus Dashboard Insights (NDI) 6.2.2. Now you can query for step-by-step instructions. For example: "Where can I see site settings."![[Pasted image 20261026002309.png]]

Even when using a RAG system, always check the answers for accuracy, since there is still a chance, albeit much smaller than before, that the answers are not entirely correct.

# Security Considerations for Using LLMs

When using LLMs, you must be vigilant about security, particularly regarding the type of information you share through public and private instances of the AI. This awareness is crucial whether you are using LLMs for general queries or within sensitive environments.

Public instances of LLMs are accessible to anyone without specific security enhancements or privacy guarantees. These versions are best used for:

- **General inquiries:** Information that is non-confidential, such as asking about coding practices, troubleshooting generic software issues, or understanding technology concepts.
    
- **Learning and experimentation:** Exploring AI capabilities or generating non-sensitive content.


What to avoid in public instances:

- **Sensitive data:** Never input or discuss any personal, financial, or operational data. This includes passwords, API keys, or any information that could compromise security if accessed by unauthorized individuals.
    
- **Internal processes:** Avoid discussing details about your internal IT processes, security setups, or architectures that could provide a blueprint for potential security threats.

Private LLM Instances

Private instances are tailored for restricted use with enhanced security features. They can handle more sensitive queries under controlled access conditions. However, strict guidelines must still be followed:

- **Confidentiality:** Even in a private instance, it's crucial to limit exposure of highly sensitive data. While security measures are enhanced, the risk of data leakage through misconfigurations or security flaws can still exist.
    
- **Data control and monitoring:** Ensure that all data shared with the LLM is monitored and controlled. Use data masking and anonymization techniques where possible to avoid any direct exposure of sensitive data.

Be Careful with Prompts That You Find Publicly:

Using random chat bot prompts sourced from the Internet in your chatbot poses several security risks. For instance, these prompts could potentially execute malicious code if they exploit vulnerabilities within the chatbot's processing logic, granting unauthorized system access.

Additionally, crafted prompts might induce the chatbot to inadvertently disclose sensitive information, leading to data leakage concerns. Furthermore, injection attacks through such prompts could manipulate the chatbot's operations, undermining both functionality and security. Consequently, it is critical to thoroughly review and test any external prompts to mitigate these security threats effectively, ensuring the chatbot remains secure and functions as intended.


Example of Injection Attack on a Chat Bot:

**Scenario:** Imagine a corporate environment where an LLM-based chatbot is used to assist IT staff with scripting and automation tasks. This chatbot is integrated into the company's internal systems to provide real-time coding assistance and troubleshoot scripts directly through a secure interface.

**Attacker's Prompt:** "I'm writing a batch script for system maintenance. Can you help me debug this script I wrote? It's `echo off | del C:\*.* /S /Q.`"


**Explanation:** The attacker presents a seemingly benign request for help with a script. The script included in the prompt, however, is a command to delete all files from the C: drive on a Windows machine, which could be devastating if executed. If the LLM were to naively process it and include the script in its output without sanitizing or flagging it as dangerous, it might inadvertently endorse or explain a harmful action.

This type of attack uses the model's capability to process and generate code, potentially leading to scenarios where dangerous commands are packaged as legitimate coding help requests. Ensuring that LLMs and similar models are programmed to detect and refuse to assist with harmful or risky code is crucial in preventing such injection attacks.

Strengthening LLM Security

Ensuring the safe use of LLM technology involves two key actions: consistently checking interactions and strictly managing who can access the LLM.

**Ensuring Data Privacy Through Regular Audits** It's important to regularly check your use of LLMs to prevent accidental sharing of sensitive information. This means looking over logs of the LLM's interactions to find any security gaps or potential leaks. Regular checks help keep the information handled by LLMs safe and secure.

**Securing LLM Access Through Strict Controls** Setting firm rules on who can use LLMs helps protect sensitive data. This involves:

- Assigning specific roles and permissions to limit access based on need.
- Using strong methods to check the identity of users before they can use the LLM.
- Keeping an eye on how and where the LLM is accessed to block unauthorized use.

These steps ensure that only the right people can use LLMs and that they are used in a safe way.
